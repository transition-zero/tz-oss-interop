# Design specs

Each file here is the design that one change agreed to before the work started. The name
gives the date of the agreement and the subject.

**A spec is history, not documentation.** It says what the design was on its date. It does
not say what the code does now. Nobody edits a spec after its branch merges. When a later
change replaces a design, that change adds a new dated spec that names the spec it
replaces.

For how the code behaves today, read `docs/developer_documentation/`. Where a spec and the
developer documentation disagree, the developer documentation is correct.
